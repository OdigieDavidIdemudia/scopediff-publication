01

The scope changed. Nobody told you.

Bug bounty programs publish a scope: the systems a hunter is allowed to test and the rewards attached to them. That scope changes quietly. A target is removed, a reward tier drops, a wildcard appears, or a target moves between groups.

There is no universal changelog. A hunter can plan a weekend around a target that was removed three days earlier, or discover a new high-value wildcard a week after everyone else. ScopeDiff turns the published scope into an append-only version history and computes the delta.

“What changed?” is not the same question as “what matters to me?”. The second question is why the product exists. A new Tier 1 wildcard matters more than an instruction edit, and a change to a host you actually test matters more than a change somewhere else in the program.

03

A small, auditable system.

The product is split into collection, canonicalisation, diff/scoring, and presentation. The free-plan build keeps the same core and replaces the paid worker host with GitHub Actions.

What is stored

Programs, immutable versions, snapshots with content hashes, target-level change items, materiality scores, source runs and per-user watches. Each change links back to the published revision and source URL.

What is not stored

No target traffic, no scan output, no exploitation data, no credentials for program systems. The demo sandbox uses RFC 2606 domains and RFC 5737 test ranges.

04

How a watch runs.

A watch is a supported program URL plus a cadence. The lifecycle is deliberately deterministic: the cron handles timing, the diff engine handles truth.

  1. Add a supported URLA Bugcrowd, HackerOne or Intigriti program page. Unknown domains are rejected instead of guessed at.
  2. Queue the baselineThe free build writes a pending watch to Firestore. The GitHub Actions cron runs every 30 minutes.
  3. Capture the first versionThe worker fetches the published scope, canonicalises targets and stores the first snapshot with a content hash.
  4. Diff and scoreOn later revisions, the engine detects additions, removals, changes, moves and reintroductions, then scores materiality and confidence.
  5. Explain and notifyThe feed, personal-impact matching and hybrid AI analyst show what changed. Slack is sent when the user’s threshold is met.
Why deterministic first

The AI is not responsible for deciding that scope changed. The diff engine is. The model explains an already-computed fact, which keeps the system auditable and makes a model failure non-catastrophic.

05

Hybrid AI, with the source in the open.

The AI Diff Analyst turns an exact scope diff into a concise summary, a why-it-matters explanation, review priorities and caveats. It uses Firebase AI Logic hybrid inference.

On supported Chrome Desktop hardware, the request runs against the on-device model. When the local model is unavailable, Firebase AI Logic automatically falls back to Gemini 3.5 Flash Lite in the cloud. The UI reports which source produced the answer and how long it took. The model is initialized from the user’s click (initializeDeviceModel()), which satisfies Chrome’s user-activation requirement before the first prompt.

The prompt contains only public diff metadata. Email, Firebase UID, Slack webhook and the user’s private testing targets are excluded. The output is constrained JSON, parsed into fixed fields and rendered as text. The model has no tools and cannot write to Firestore.

const model = getGenerativeModel(ai, {
  mode: InferenceMode.PREFER_ON_DEVICE,
  inCloudParams: {
    model: "gemini-3.5-flash-lite",
    generationConfig: {
      responseMimeType: "application/json",
      responseSchema: schema
    }
  },
  onDeviceParams: {
    createOptions: {
      expectedInputs: [{ type: "text" }],
      expectedOutputs: [{ type: "text" }]
    },
    promptOptions: { responseConstraint: schema }
  }
});

await model.initializeDeviceModel();
const result = await model.generateContent(prompt);
console.log(result.response.inferenceSource);
// "on_device" or "in_cloud"

The AI action first calls await model.initializeDeviceModel() inside the click handler, then sends the prompt.

Privacy by architecture

On-device inference is the preferred path because the prompt stays local. The cloud fallback is explicit, not silent: the user sees the inference source and can decide whether to trust the result. The deterministic diff remains the source of truth.

Guardrails, including the uncomfortable ones.

A scope watcher is only useful if its alerts are trustworthy. These are the controls that keep the feed honest — and the ones still being hardened.

07

Safety and authorisation.

ScopeDiff is a change-communication tool, not an attack tool. It reads public program metadata to answer one question: what changed in the published rules?

Authorised testing only. Only test systems you own or have explicit written authorisation to test. ScopeDiff does not grant permission, expand a program’s scope or replace a program’s rules.

No scanning or exploitation. The product does not resolve, probe, fuzz, exploit or otherwise touch a target. It does not provide payloads or attack automation. The AI analyst is explicitly prompted to use review language and is not given tools.

Reserved values in examples. Every demo target uses RFC 2606 domains such as example.com and RFC 5737 ranges such as 192.0.2.10. Seeded programs are fictional.

Dual-use boundary

The publication explains the method, architecture and scoring model. It does not publish a ready-to-run evasion or exploitation sequence, and it does not include real program tokens or private endpoint data.

08

What this build does not do.

Honest limitations

  • The free plan checks every 30 minutes, not every minute.
  • Queued baselines wait for the next GitHub Actions run; there is no instant fetch.
  • Email digest is stored as a preference only. Slack is the implemented channel.
  • App Check and strict API-key restrictions are not yet enforced for the AI endpoint.
  • On-device inference is Chrome-on-Desktop only; other browsers use cloud fallback.
  • Prompt injection is a bounded partial risk because scope metadata is untrusted public content.
  • The FastAPI worker is not hosted on the free plan; Cloud Run would require billing.

Out of scope

  • Vulnerability discovery, scanning, exploitation or proof-of-concept generation.
  • Guaranteeing that a published change was intentional or authorised.
  • Replacing a program’s rules, disclosure policy or legal terms.
  • Monitoring private, authenticated or non-public program pages.
  • Arbitrary website scraping. Only supported platform URLs are accepted.
